Windows Server 2016, fin de support le 12 janvier 2027 : options et calendrier

Le 12 janvier 2027, Windows Server 2016 reçoit son dernier correctif de sécurité gratuit. Voici le calendrier exact, les quatre options possibles et la méthode pour décider serveur par serveur, avant la date.

Par Amine, ingénieur DevOps freelance · Mis à jour le 3 novembre 2026

Le support étendu de Windows Server 2016 se termine le 12 janvier 2027 ; le support standard a pris fin le 11 janvier 2022. Après cette date, plus de correctifs de sécurité gratuits. Quatre options : mise à niveau sur place vers Windows Server 2025 (prise en charge depuis 2016), réinstallation avec migration des rôles, mises à jour de sécurité étendues (ESU) payantes pendant trois ans au plus, ou remplacement par un service géré. Commencez par l'inventaire, puis par les contrôleurs de domaine.

Microsoft a publié ces dates sur son blog Windows IT Pro et dans la documentation d'Azure Arc. Si vos serveurs Windows Server 2016 hébergent aussi SQL Server 2016, ce dernier est déjà hors support étendu depuis le 14 juillet 2026 : les deux chantiers gagnent à être traités ensemble.

Ce qui se passe après le 12 janvier 2027

Le serveur continue de fonctionner. Mais chaque vulnérabilité découverte après cette date reste ouverte, alors que les correctifs publiés pour les versions supportées indiquent précisément où chercher. Les conséquences dépassent la sécurité :

  • les éditeurs de logiciels cessent progressivement de supporter leurs applications sur un système hors support ;
  • les assureurs cyber et les auditeurs demandent de plus en plus la liste des systèmes hors support et le plan pour en sortir ;
  • vos clients soumis à des réglementations comme NIS 2 ou DORA peuvent exiger que leurs fournisseurs n'exploitent pas de systèmes obsolètes.

Les quatre options

1. La mise à niveau sur place

Windows Server 2025 accepte la mise à niveau directe depuis Windows Server 2012 R2, 2016, 2019 et 2022, en sautant jusqu'à quatre versions d'un coup pour un serveur hors cluster. Les applications et les données restent en place. C'est rapide pour un serveur simple, mais l'historique du serveur le suit, et tous les rôles ne supportent pas la mise à niveau : Microsoft publie une matrice des rôles et fonctionnalités à consulter avant. Changer de langue ou passer d'une installation Core à une installation avec interface n'est pas possible pendant une mise à niveau.

2. La réinstallation avec migration

Un serveur neuf en Windows Server 2025, puis migration des rôles et des données : partages de fichiers, impression, DHCP, IIS, applications métier. Plus long, mais plus propre. C'est la méthode à privilégier pour les contrôleurs de domaine et les serveurs chargés d'historique. Si vous quittez VMware en même temps, le nouveau serveur peut être installé directement sur la nouvelle plateforme : une seule migration au lieu de deux.

3. Les mises à jour de sécurité étendues

Microsoft propose des ESU pour Windows Server 2016 pendant trois ans au plus. Via Azure Arc, elles se configurent depuis août 2026 et sont facturées à partir du 13 janvier 2027 ; l'achat suppose en général la Software Assurance. Les ESU ne livrent que les correctifs critiques et importants : ni nouvelles fonctionnalités, ni correctifs non liés à la sécurité. Microsoft n'avait pas publié de grille tarifaire publique au moment de l'annonce, et la presse spécialisée s'attend à un coût élevé : demandez un chiffrage à votre revendeur avant de compter dessus. Les ESU conviennent à une application impossible à migrer à temps, avec une date de sortie écrite, pas à tout un parc.

4. Le remplacement par un service

Certains rôles n'ont plus besoin d'un serveur : messagerie, partage de fichiers, impression ou annuaire peuvent passer à des services gérés. C'est à étudier rôle par rôle, en tenant compte de vos contraintes de localisation des données.

Les cas qui demandent plus de soin

  • SQL Server sur le même serveur. Mettre à niveau le système sans traiter SQL Server 2016, lui-même hors support étendu, ne règle que la moitié du problème. Vérifiez la version de SQL Server prise en charge par l'éditeur de votre application avant de choisir la cible.
  • Les serveurs Bureau à distance. Les serveurs RDS cumulent rôles, profils utilisateurs et applications installées : une nouvelle ferme en Windows Server 2025, testée par quelques utilisateurs avant la bascule, est généralement plus sûre qu'une mise à niveau.
  • Les applications métier anciennes. Certaines ne sont plus maintenues par leur éditeur. Testez-les sur une copie du serveur avant toute intervention, et prévoyez les ESU si le test échoue.
  • Les serveurs physiques. Le matériel doit être compatible avec Windows Server 2025, pilotes compris. Une machine trop ancienne est souvent l'occasion de virtualiser le serveur plutôt que de le remplacer à l'identique.

La méthode, d'ici janvier 2027

  1. Inventorier. Tous les serveurs en Windows Server 2016, leurs rôles, leurs applications, la version de SQL Server, les dépendances. Un export RVTools donne la liste des VM et de leur système en quelques minutes.
  2. Classer. Pour chaque serveur : mise à niveau, réinstallation, service géré ou ESU. Vérifiez auprès des éditeurs que leurs applications sont supportées sur Windows Server 2025.
  3. Commencer par l'annuaire. Les contrôleurs de domaine conditionnent tout le reste : nouveaux contrôleurs en 2025, transfert des rôles, puis retrait des anciens.
  4. Migrer par lots. Les serveurs les moins critiques d'abord. Sauvegarde vérifiée avant chaque intervention, retour arrière prévu.
  5. Couvrir le reste. Pour les serveurs qui ne seront pas prêts au 12 janvier 2027, commandez les ESU à temps et fixez une date de sortie.

Questions fréquentes

Mon serveur Windows Server 2016 s'arrêtera-t-il le 12 janvier 2027 ?

Non, il continuera de fonctionner. Il ne recevra simplement plus de correctifs de sécurité gratuits : chaque faille découverte ensuite restera ouverte, sauf si vous achetez des mises à jour de sécurité étendues.

Combien coûtent les ESU de Windows Server 2016 ?

Microsoft vend les ESU par l'intermédiaire des contrats en volume ou d'Azure Arc, en général sous condition de Software Assurance. Le prix dépend de votre contrat et du nombre de cœurs : demandez un chiffrage à votre revendeur et comparez-le au coût d'une migration.

Faut-il passer à Windows Server 2019, 2022 ou 2025 ?

Windows Server 2025 offre la période de support la plus longue, et Microsoft recommande cette cible. Une version intermédiaire ne se justifie que si une application n'est pas encore certifiée sur 2025.

Peut-on mettre à niveau un contrôleur de domaine ?

C'est possible, mais la pratique la plus sûre consiste à installer un nouveau contrôleur de domaine en Windows Server 2025, à lui transférer les rôles, puis à rétrograder et retirer l'ancien. Microsoft publie une procédure dédiée à la mise à niveau des contrôleurs de domaine.
